# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A collection of POSIX shell and Python scripts that mirror the Toyota/Lexus/Scion Factory Service Manual (FSM) from TIS (https://techinfo.toyota.com) for personal offline use, then post-process it into a locally browsable website and optional PDFs. There is no build system, package manager, or test suite. The scripts run against the live site and need an authenticated, paid TIS session. End-user steps are in `HOWTO.md`. Known gaps and wishlist items are in `FUTURE.md`.

## Configuration model (read this first)

Every script starts by sourcing `$HOME/.tis/tis-clone.cfg`, **not** the copy in the repo. `setup.sh` copies `tis-clone.cfg` to `~/.tis/` only if no copy exists there yet. If you change defaults in the repo's `tis-clone.cfg`, existing installs won't pick them up. Key variables:

- `BASE` / `SCRIPT_BASE`: repo location (assumed to be `~/tis-clone`). Scripts call each other through `${SCRIPT_BASE}/...`, so the repo must sit at `$BASE`.
- `DOWNLOAD_TO`: download working directory. Files land in `$DOWNLOAD_TO/techinfo.toyota.com/`, which is `FSM_URLBASE`. `tis-fetch.py` keeps its `MANIFEST` in `$DOWNLOAD_TO`.
- `WG` / `WG_NOMIRROR`: old wget command lines. Nothing uses them any more, but existing `~/.tis` configs may still define them. Their lessons live on in `tis-fetch.py`: a 0.5 s delay between requests (downloading too fast gets the session logged out as a duplicate login) and writing rotated cookies back to `cookies.txt` (a stale cookie file looks like a second login, issue #11).
- `SIID`: the `siid=` value appended to every document request. `setup.sh` writes a random one into a newly created `~/.tis/tis-clone.cfg`.
- `COOKIES` (`~/.tis/cookies.txt`): written by `scripts/tis-login.sh`.
- `TIS_USERNAME` / `TIS_PASSWORD` / `TIS_MFA` (optional; commented out in the repo template): defaults for `tis-login.sh`. Its `-u`/`-p`/`-m` flags override them. Never print or commit a real password.
- `MYURL`: your public site, if any. `tis-pdfbook.py` points links to other manuals there, or drops them when it's localhost. `MYURL_BASE` is only used by the legacy `tis-pdfer.sh`/`tis-html2pdf2.sh`.

Python scripts read config by shelling out: `load_cfg()` runs `sh -c '. "$HOME/.tis/tis-clone.cfg" && printf "%s\\0" ...'`. There is no Perl left.

## Pipeline / architecture

`./tis-clone [CODE] [--rm|--ewd|--bm|--nm CODE] [--no-pdf]` (repo root, POSIX sh) runs the whole pipeline. It probes every candidate toc/termdata in one `tis-fetch.py --no-requisites` call: `rm/RM`, `ewdappu/{EM,EWD,}` plus `ewd/{EWD,EM,WD}`, `cr/{BM,CR,BR}`, `ncf/{NM,NCF}`. Then it runs the matching `dl-*.sh` for each manual that exists. A section missing on TIS is skipped when it comes from CODE, and is an error when named with `--<section>`. Next it runs `dl-framework.sh`. Only if every download exited 0 does it run `tis-urlstripper.sh` and `build-index.py`, then PDFs (`tis-mkpdfs.sh` per code, `build-pdfidx.sh`, index again). Exit 75 or 130 stops it at once, with a hint to use `--resume`. It saves `ARGS`, `TODO` (the probed `script:code` list), `NOTFOUND`, `DONE <script:code>` / `DONE pdf:<code>` and `FINISHED` lines in `$DOWNLOAD_TO/tis-clone.resume`. `--resume` re-reads `ARGS` (codes are validated as `[A-Za-z0-9]+`, since they're re-split from that file), reuses `TODO` without probing, and skips `DONE` steps. Every run first runs `tis-verify.py --last 20 --fix` to catch files cut short by a crash. The website steps always rerun because they're cheap. The steps below are what it runs.

1. **Auth:** `tis-login.sh` (bash + curl + python3) uses Toyota's OpenAM REST API with email/SMS MFA and writes a Netscape cookie file. It only saves the cookies if they can fetch the `glossary.pdf` test page. The portal landing page sometimes returns 403 even though the session works, so the landing page isn't used as the success test. On failure it saves the portal page to `~/.tis/last-login-portal.html`. `confirm-login.sh` is `tis-fetch.py --check`: it fetches the same test PDF and exits 75 with the reason (login page or redirect, not logged in, unreachable) if the session doesn't work.
2. **Download:** documents are keyed by a 5-character GSIC code (e.g. `27J0U`), prefixed per manual type to form TIS paths such as `/t3Portal/external/en/rm/RM27J0U`. Manual types are RM = repair, EM/EWD = wiring, BM/CR = body/collision, NM/NCF = new car features. Recent vehicles use BM (titled "Collision Repair manual") and NM. The CR and NCF tocs 404, which the scripts report as a wrong identifier.
   - `tis-fetch.py` is the resumable downloader (Python and requests, no wget). It takes URLs or `/t3Portal/...` paths as arguments or with `-i FILE|-`, and also fetches each page's images, CSS, JS and linked files. It doesn't follow `<a href>` to other `.html` documents, because they are all in `toc.xml`. It saves files under the path without the query string, follows "PDF" stubs that are a `<script>location='…?locale='` redirect, and writes files atomically. Progress goes to a plain-text `$DOWNLOAD_TO/MANIFEST` (`STATUS\tPATH\tBYTES\tTIME\tNOTE`, last line per path wins). OK, MISSING and FORBIDDEN paths are skipped on rerun and FAILED ones are retried. It treats a 403, a redirect to login, a login-page body, or the wrong file signature as a possible dead session and confirms with the `glossary.pdf` test page. A confirmed dead session runs `tis-login.sh` on `/dev/tty` and retries the same URL. Each attempt sends a 2FA code and the user may be away for hours, so `relogin()` rings the bell and waits for Enter on `/dev/tty` before every attempt. A `q` or EOF returns False, which makes the run exit 75. After Enter it sends no code if `portal_problem()` says TIS isn't answering, and asks again instead. A failed login also asks again. There are no timed retries. Without a terminal, or with `--no-relogin`, it exits 75. It writes rotated cookies back to `cookies.txt`. Each file is fsynced before its rename and the MANIFEST is fsynced after each line, so an OK entry always means the file is complete on disk, even after a power cut. The session is only checked before the first item that actually needs downloading, so a rerun whose files are all done needs no login. Two TIS quirks are handled: PNGs served under `.gif`/`.jpg` names (any image signature is accepted for image extensions), and `.svgz` sent with `Content-Encoding: gzip` (the raw gzip bytes are saved instead of letting requests decode them).
   - `dl-html-{rm,bm,cr,nm,ncf}.sh` are thin wrappers that build the folder URI and call `dl-html-inc.sh`. That script runs `tis-fetch.py` on `toc.xml` and then on every `*.xhtml` it lists (with `?sisuffix=…&siid=${SIID}` appended), then generates `toc.html` via `toc2html.py` and copies in `website-framework/index.html`. Rerunning it resumes from the manifest.
   - `dl-html-ewd.sh` is the most complex downloader. It also uses `tis-fetch.py`, in phases: probe `EM<code>`, `EWD<code>` and then the bare `<code>` under `ewdappu/` for `termdata.xml`; fetch the viewer pages, intro and per-model-year contents lists; fetch tree pages named in those lists (repeated until no new ones appear); then fetch the figures (SVG, SVGZ, PDF, PNG, MP4) named in the contents XML. Each phase builds its URL list from files the previous phase downloaded. Wiring pages are displayed inside `ewd/ewd_index.html`, so their links are relative to `ewd/`, and the script passes `--base .../ewd/` to tis-fetch. Missing tree pages (~120 per model year), `zoombar_08`/`09`, and some intro pages are genuine 404s upstream.
   - TIS refuses a few `.svgz` figures, so `dl-html-ewd.sh` gzips the matching `figsvg/*.svg` into `fig/`. It also strips DOS line endings from the URL lists.
   - `dl-framework.sh` uses `tis-fetch.py` (with `--scope /` for `/favicon.ico`) to fetch the shared TIS viewer framework: scripts the EWD viewer loads at runtime, the icons, and `all-t3.css` (its images include the header bar that `build-index.py`/`build-pdfidx.sh` use). Newer EWD viewers probe `contents/routing/fig-pos` and request `fig-pos/` with an empty name; those 404s are harmless, because no manual seen so far has `<fig-pos>` data. The TIS siviewer navigation pages (`resources/jsp/siviewer/*.jsp`) are deliberately not fetched, because nothing in the local site uses them. Only their icons are used. It then patches `ewd.js` (forces uncompressed SVG) and `all-t3.js`. Each patch is regenerated from a saved `.orig` and recognises a freshly downloaded unpatched file, so the script can run before or after `dl-html-ewd.sh`.
   - `dl-pdf-*.sh` are for older (≈1990–2000) vehicles whose content is PDFs linked from xhtml. They're 3-line wrappers that call `dl-pdf-any.sh <type>/<PREFIX><code>`, which calls `dl-html-inc.sh`. The xhtml pages link their PDF with a plain `<a href>`, so tis-fetch's requisite handling fetches it, including the `?locale=` redirect stubs that the old wget version saved in place of PDFs (all 65 NM0800U "PDFs" in the LC200 copy are stubs).
   - `dl-anypage.sh` runs `tis-fetch.py --scope /` on the given pages: each page plus its assets, with no recursive crawl. The old `wget -m` crawled recursively.
   - No script uses wget any more.
   - `tis-report.py` reads the MANIFEST (last line per path wins) and reports per manual, keyed by `MANUAL_RE`/`EWD_RE` → the `dl-*.sh` that reruns it. It lists FAILED/FORBIDDEN with notes and groups MISSING by folder, tagging normal 404s (`NORMAL_MISSING`, plus a missing `toc.xml`/`termdata.xml`, which means the manual type doesn't exist). GONE means OK in the manifest but absent on disk. MISSING/FORBIDDEN files that exist on disk (made locally, e.g. `.svgz` from `.svg`) and EWD folder-URL entries are not problems. It also prints non-zero exits from `tis-clone.log`. `--retry` appends `FAILED` lines so the next run refetches FORBIDDEN/MISSING/GONE. Add new known-normal 404s to `NORMAL_MISSING`.
   - `tis-verify.py` (`tis-verify.sh` wraps it) checks files on disk, not the manifest. It looks for login pages (`LOGIN_RE`) in pages and in scripts that start with `<`, `?locale=` stub PDFs, wrong signatures (any image signature is accepted for image extensions), non-`ftyp` `.mp4`s, empty files (except `.do`), and toc.xml docs that are absent (unless the manifest says MISSING/FORBIDDEN). It skips `PDFs/`, `framework/`, `*.orig`, generated `toc.html` and wget `?` names. `--fix` appends FAILED for bad files and OK for good files the manifest lacks. That "adopts" an old wget download, so the `dl-*` scripts then refetch only the bad files. On LC200 it finds about 8,700 bad files (login pages in five EWDs and stub PDFs in NM0800U/NM18X0U), and the RAV4 copy checks clean.
3. **Clean-up:** `tis-urlstripper.sh` deletes `*linkId=*` redirect duplicates and strips absolute TIS hostnames from xml/html/xsl/js/css/jsp (and `.orig`) files so the mirror works on localhost. It greps for the hostnames first and runs one inline Python over only the files that match (each rewritten via a `.part` file and rename, keeping its mode), so rerunning it is cheap.
4. **PDFs (optional):** `tis-mkpdfs.sh <code>` runs `tis-pdfbook.py <toc.xml> PDFs/<model>/<Type>-<DOCID>.pdf` for each `document/*/<DOCID>/xhtml` folder matching the code, with `<model>` from `toc2topic.py`. The wiring diagrams are still Ghostscript joins of `ewd/contents/{overall,relay,routing,system}/pdf/*.pdf`. `tis-pdfbook.py` makes one PDF per manual so that every link can be internal, which is what works in all viewers (cross-file GoToR doesn't):
   - It serves `FSM_URLBASE` on 127.0.0.1 via `tis-serve.start_server` (8080 or the next free port; it imports `tis-serve.py` with importlib) using `PrintHandler`. That handler rewrites each `xhtml/*.html` in flight: `<a name>` gets an `id` and `display:block;height:0` (wkhtmltopdf only positions anchors that have an id and a box; TIS's `<a name="X"> </a>` collapse to nothing), and a 1px transparent link to every anchor is appended (wkhtmltopdf only records destinations for anchors that something links to).
   - It runs wkhtmltopdf per page in a thread pool, caching in `$DOWNLOAD_TO/pdfwork/<WORK_VERSION>/<DOCID>/`. Bump `WORK_VERSION` when rendering changes. Pages with `<link rel="pdf">` (PDF-era manuals) use that PDF directly.
   - It merges with pikepdf from in-memory copies (sources stay referenced until save). It collects each page's old-style `/Root /Dests` entries named `http://127.0.0.1:PORT/path#frag` (`[int page, /XYZ, x, y, z]`) into (path, frag) → merged page and y. Then it rewrites every Link whose `/Dest` name or `/A /URI` starts with the server base into an explicit `[page /XYZ null y null]`, falling back to the target page's top, or `MYURL`, or drops it. It drops the helper links (narrower than 4pt). It builds the outline from the toc.xml tree and shares identical image XObjects (`share_images`, about 30% smaller).
   - Verified on RM30B0U: 15,066 pages, 31,901 links all internal, and 397 of 400 sampled anchors had their text on the linked page (the 3 misses were text-extraction quirks).
   - `tis-xhtml2pdf.sh` (the per-page, `/t3Portal` symlink, Ghostscript-join method) is legacy and unused.
5. **Navigation:** `build-index.py` scans for `toc.html` (title from its `<title>`) and EWD `ewdappu/*/xhtml/termdata.xml` (title from `<pubtitle>`, XML-parsed; saved error pages are skipped) and prints a top-level `index.html` to stdout. `toc2html.py` makes each manual's `toc.html`: a 3- or 4-level Bootstrap menu (toc.xml hrefs are always at depth 4, or 3 for old WD manuals), with TIS's no-break-space padding turned into spaces. `build-pdfidx.sh` does the same for PDFs. Both use the Bootstrap/jQuery assets in `website-framework/framework/`.
6. **Publish:** `tis-merge.sh <target>` rsyncs the current directory into a live site tree.

The mirror's `index.jsp` loads XHTML dynamically with JavaScript, so it must be served over HTTP, not opened via `file://`. Use `scripts/tis-serve.py`, Apache/nginx with `.jsp` mapped to an HTML MIME type, or Abyss per `ABYSS.md`. `tis-serve.py` serves `.jsp` as text/html and `.svgz` with `Content-Encoding: gzip`. Plain `python3 -m http.server` serves `.jsp` as a download, which breaks the wiring diagram viewer (its entry page is `ewdappu/index.jsp`).

## Working on the scripts

- Check dependencies and create directories: `./setup.sh`. It checks for bash, curl, python3 (with `requests` and `pikepdf`), gzip, xargs, gs, wkhtmltopdf's patched-qt build (warning only), poppler, pdftk, rsync, and wkhtmltopdf. Perl is not needed.
- Run one downloader manually: `. ~/.tis/tis-clone.cfg && cd $DOWNLOAD_TO && ~/tis-clone/scripts/dl-html-rm.sh 27J0U`.
- When the TIS session expires (it lasts about 5 hours), TIS answers **403 with the login page as the body**. The April 2026 LC200 log (`~/tis-download-lc200/dl.out`) shows this.
- No automated tests. Validate with `sh -n script.sh` / `python3 -m py_compile` locally. Real verification needs a logged-in TIS session and hits the live site, so don't run downloaders without the user's go-ahead.
- Style: most scripts are `#!/bin/sh` using backticks, `[ x$1 = x ]` argument checks, and tab indentation. Keep to that. `tis-login.sh` is the exception (bash).
- `tis-fetch.py` output is one `[STATUS] path` line per file, plus the MANIFEST.
- Logging: every script except the ones that print data to stdout (`build-index.py`, `build-pdfidx.sh`, `toc2html.py`, `toc2topic.py`) sources `scripts/tis-log.sh` on the line after it loads the config. The first script in a run re-runs itself as `{ trap ':' INT; "$0" "$@" 2>&1; echo $? > rcfile; } | tee -ia $TIS_LOG`, with the log defaulting to `$DOWNLOAD_TO/tis-clone.log` (mode 600). It writes `===== date start:` and `===== date exit N:` lines around the run and exits with the script's status. It exports `TIS_LOGGING=1` so nested scripts and `tis-fetch.py` don't log twice, and `PYTHONUNBUFFERED=1`. `tis-fetch.py` and `tis-serve.py` do the same via `scripts/tislog.py` `tee_to_log(cfg)`. `tis-fetch.py` calls it before reading `-i -`, so the re-run still gets stdin. New scripts should follow the same pattern. Because the re-run goes through a pipe, stdout is never a tty inside a logged script.
- Ctrl-C: the trap (a handler, not `''`, because an ignored signal would be inherited) keeps the wrapper alive until the script finishes, and `tee -i` keeps logging. The script itself still gets SIGINT, so tis-fetch prints "Interrupted", saves cookies and exits 130.
- Documentation: `HOWTO.md` has the user steps and a script reference. Keep it in step when adding or changing scripts or options.
